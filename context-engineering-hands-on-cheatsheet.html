1. The Four Levers — Write · Select · Compress · Isolate
WRITE — Create
  • Plans & scratchpads during a task
  • Learned memories across sessions
  • Filesystem logs & progress files
  • Write claims + sources to verify

→ todo.md, plan files, JSON logs

SELECT — Pull
  • Agentic retrieval (grep, glob, fetch)
  • Tool loadout: only what's needed
  • Progressive disclosure vs. stuffing
  • llm.txt + fetch tool (Lance Martin)

→ Claude Code: no indexing, pure agentic retrieval

COMPRESS — Shrink
  • Offload to disk first (lossy safety net)
  • Summarize with high recall (exhaustive bullets)
  • Auto-compact at 95% capacity (Claude Code)
  • Trim verbose tool outputs after processing
  • Cache invariant context (system prompts)
ISOLATE — Separate
  • Sub-agents: clean window, summary return
  • Sandbox: persists state (images, data files)
  • State objects (Pydantic): expose fields selectively per stage
  • Read tasks parallelize — write tasks don't
2. Four Failure Modes + Fixes (Drew Breunig's Taxonomy)
POISONING — Hallucination compounds

A bad output enters context and is repeatedly referenced as ground truth. Agent becomes fixated on impossible goals (Gemini Plays Pokémon).

FIX: ISOLATE + SELECT
  • Keep raw tool outputs in separate state fields
  • Promote only validated facts into next prompt
  • Write a scratchpad of claims + sources; forward verified only
DISTRACTION — Model ignores training

Context grows so long the model over-focuses on it. Gemini 2.5 Pro: ↓ performance beyond 100K tokens; defaulted to repeating past actions. Llama 3.1 405B ceiling: ~32K.

FIX: COMPRESS + SELECT
  • Periodically summarize history; reinitiate with summary
  • Pull smaller working set each step
  • Write persistent plan so you can compress without losing intent
CONFUSION — Irrelevant content pollutes

If you put it in context, the model attends to it. Berkeley: Llama 3.1 8B failed with 46 tools — succeeded with 19. Every model worsens with more tools.

FIX: SELECT + ISOLATE
  • Dynamic tool loading (LLM-powered recommender: +44% Llama 3.1 8B)
  • Keep "nice-to-have" context in separate state fields
  • DeepSeek-v3 fails at 100+ tools — keep loadouts small
CLASH — Conflicting context compounds

New info conflicts with earlier context. Microsoft/Salesforce: 39% avg drop when identical info spread across turns. o3: 98.1 → 64.1. Wrong turns don't self-correct.

FIX: ISOLATE + SELECT
  • Context quarantine: multi-agent isolated context → +90.2% on parallelizable tasks
  • Apply precedence rules to decide what's included this step
  • Compress conflicting sections into single resolved summary
3. Context Prioritization & Debugging Loop
Context Prioritization Tiers
  • CRITICAL — current code, error messages, active task → always include
  • HELPFUL — project structure, conventions → if space permits
  • OPTIONAL — historical decisions, background → only if needed
"Find the smallest set of high-signal tokens that maximize the likelihood of your desired outcome."
— Anthropic, Effective Context Engineering for AI Agents

Models can ignore irrelevant info but cannot perform without relevant info — prioritize recall.

The Debugging Loop
  1. Inspect trace — walk through messages, tool calls, and outputs turn-by-turn
  2. Tag failure — which of the four modes? (Poisoning / Distraction / Confusion / Clash)
  3. Pick a lever — W / S / C / I based on the mode (Select appears in every fix)
  4. Re-run & evaluate — measure outcome quality, not just token count
  5. Iterate — context engineering is cyclical, not one-shot

Context pruning reduced a Wikipedia article by 95% while preserving QA accuracy. Offload + domain prompts: up to +54% performance.

5. Claude Code Primitives → Lever Mapping
Primitive → Lever
  • CLAUDE.md → WRITE — Minimal static context; routing table not content dump. Human-written, <150–200 instructions.
  • Slash commands → WRITE — Reusable prompts authored once. /audit-context /ci_commit /review
  • Hooks → COMPRESS + ISOLATE — post-tool-use, pre-commit, session-start. Sidecar files without changing prompts.
  • Sub-agents → ISOLATE — Clean window, scoped toolset, summary-only return to parent.
  • MCP servers → SELECT — Composable context primitives, vendor-agnostic. Use fully qualified names (Server:tool_name).
CLAUDE.md — What Works

ETH Zurich (arXiv 2602.11988): agents follow CLAUDE.md and use mentioned tools 1.6–2.5× more — but this costs 14–22% more reasoning tokens without solving more tasks.

✓ Put IN:

  • Project purpose (one line)
  • Non-obvious commands (build, test, deploy)
  • Hard-to-infer conventions & package manager quirks

✗ Keep OUT:

  • Anything already in README or code comments
  • Anything the agent can ls to discover
  • LLM-generated content (−3% success, +20% cost)

Claude Code system prompt already uses ~50 instructions — budget the remaining ~100–150 carefully.

6. Pattern Selection Guide
When to Use Which Pattern
Situation Pattern Why
Stable project conventions Minimal CLAUDE.md Rarely changes; static is fine
Topic-specific research Context priming at session start Fetches current docs, not stale weights
Large codebases, many tools Dynamic discovery + tool consolidation Avoids Confusion; 46.9% token savings (Cursor)
Long-running multi-step agents Tiered architecture + filesystem Hot/cold separation; pre-rot at 70–80%
Multi-agent systems Communication over shared context "Share memory by communicating" — Peak Ji (Manus)
Repetitive learnable workflows Self-improving contexts (ACE) No manual maintenance; contexts evolve from execution

8. Production Lessons — Manus Five Strategies (Peak Ji)
Five Strategies for Production Context
  1. Compaction & summarization — reversible (paths, not contents) + lossy at ~128K tokens; always offload before summarizing
  2. Communication over shared context — fresh sub-agents for discrete tasks; never let agents share a growing context window
  3. Hierarchical action spaces — ~20 atomic tools + sandbox utilities + code libraries for complex chains
  4. Agent-as-tool — sub-agents as deterministic functions with JSON schemas; parent sees only structured output
  5. Pre-rot thresholds — trigger compaction at 70–80% utilization, proactively (not at overflow)
